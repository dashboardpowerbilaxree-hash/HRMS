   363→ROOT CAUSE (why previous fix showed 0 leaves for everyone)
   364→==========================================================
   365→The bulk-upload route (src/app/api/attendance/bulk-upload/route.ts)
   366→creates an attendance record with status='absent' whenever an employee
   367→doesn't punch in. So when an employee takes a full-day leave (no punch
   368→in), there are TWO records for the same day:
   369→  1. A Leave table record (approved leave)
   370→  2. An Attendance table record with status='absent'
   371→
   372→The previous fix (commit e17b5f5) only counted a leave when there was
   373→NO attendance record. But because bulk-upload ALWAYS creates an 'absent'
   374→record for no-show days, the leave check never matched — every leave
   375→day was being treated as a plain absent day, and the Leave column
   376→showed 0 for everyone.
   377→
   378→THE FIX
   379→=======
   380→In export-master/route.ts, when an attendance record exists AND its
   381→corrected status is 'absent':
   382→  - Check if that day is in the employee's approved-leave set
   383→  - If yes (and not Sunday/holiday): count as LEAVE, display 'Leave'
   384→  - If no: count as ABSENT, display 'Absent' (unchanged behavior)
   385→
   386→Half-days are STILL not counted as leaves — they remain 0.5 present +
   387→0.5 absent, matching the user's expectation:
   388→  2 full-day leaves + 1 half-day = 2 leaves (not 3, not 0)

   507→ROOT CAUSE FOUND
   508→================
   509→Discovered a THIRD bug (beyond the two previous fixes):
   510→
   511→The leave database query in 6 API routes used:
   512→  startDate: { gte: startOfMonth }, endDate: { lt: endOfMonth }
   513→
   514→This MISSED leaves that span month boundaries. Example:
   515→- Production has a leave for EMP-021 from June 27 to July 1 (5 days)
   516→- The July query required leave.startDate >= July 1
   517→- But this leave's startDate is June 27 (< July 1)
   518→- So the leave was EXCLUDED from July entirely
   519→- Result: July Master Excel showed 0 leaves for EMP-021
   520→
   521→This is why production showed 0 leaves for everyone — the only July
   522→leave was a month-spanning one that the query missed.
   523→
   524→THE FIX
   525→=======
   526→Changed the leave query in all 6 affected routes to an OVERLAP query:
   527→  startDate: { lt: endOfMonth }, endDate: { gte: startOfMonth }
   528→
   529→This catches any leave that overlaps the target month, including
   530→leaves starting in the previous month or ending in the next month.
